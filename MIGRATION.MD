# gentle-claude — Migration Plan

Architecture analysis conducted 2026-07-25.
Sources: live fetch of `Gentleman-Programming/gentle-ai`, `earendil-works/pi`, local repo.

---

## TL;DR

The architecture is fundamentally correct. gentle-claude is a thin 4-hook adapter
that delegates all intelligence to the `gentle-ai` binary. The problem is ~170 LOC
of accumulated maintenance risk — fragile parsing of unstable CLI output, auto-side
effects the plugin should not own, and a manual session-snapshot round-trip that
duplicates what the Engram MCP server already handles.

**Action: subtraction, not rewrite.**

Current: ~350 LOC across 4 scripts.
Target: ~180 LOC across 5 files.

---

## Diagnosis Summary

| # | Defect | File(s) | Risk |
|---|--------|---------|------|
| 1 | `sdd-status` parsed via regex over markdown-fenced JSON | `user-prompt-submit.py` + `session-stop.py` (duplicated) | High — silent breakage on any output change |
| 2 | Review-status parsed identically in two places | both files | Medium — duplicated fragile code |

| 5 | Manual engram CLI round-trip for session snapshots | `session-start.py` + `session-stop.py` | High — duplicates Engram MCP; two interfaces to same store |

## Stable vs Unstable gentle-ai Surfaces

**Stable (use these):**
- `gentle-ai review [...] --contract gentle-ai.review-integration/v1`
- `gentle-ai skill-registry refresh`
- `gentle-ai doctor`, `gentle-ai --version`
- `.atl/skill-registry.md` — markdown table, generated by gentle-ai
- JSON schemas in `contracts/review-integration/v1/schemas/`

**Unstable (avoid these):**
- `gentle-ai sdd-status` — no schema, no versioning, markdown-fenced JSON output
- `engram search/save` CLI — output shape is not contractual
- `~/.claude/settings.json` — read directly, bypassing any gentle-ai abstraction

## Phase 1 — Extract shared module ✅ DONE

**File:** `scripts/gentle_ai.py` (new, ~40 LOC)
**Effort:** ~2h

### What to do

Extract the copy-pasted `run()` helper and CLI wrappers into a single shared module.
Currently the same subprocess boilerplate lives in all three scripts.

```python
# scripts/gentle_ai.py
def run(cmd, timeout=10, cwd=None) -> tuple[bool, str]:
    """Run a gentle-ai CLI command. Returns (ok, stdout)."""
    ...

def review_status(cwd: str) -> dict:
    ...

def review_validate(gate: str, cwd: str) -> tuple[bool, str]:
    ...

def version() -> str:
    ...

def doctor() -> list[str]:
    ...
```

### Why

All three hook scripts duplicate the same `subprocess.run` pattern with identical
error handling. Centralizing here makes future changes a one-line edit.

### Files touched

- `scripts/gentle_ai.py` — CREATE
- `scripts/session-start.py` — import and use
- `scripts/user-prompt-submit.py` — import and use
- `scripts/session-stop.py` — import and use

### Tests

- Update `tests/conftest.py` to mock `gentle_ai.run` at the module level
- All existing tests should pass after import refactor

## Phase 2 — Remove fragile SDD status parsing ✅ DONE

**Effort:** ~1h
**Blocks:** nothing downstream depends on SDD context injection

### What to do

Delete `get_sdd_status()` from `user-prompt-submit.py` and `sdd_snapshot()` from
`session-stop.py`. Both functions use an identical regex:

```python
re.search(r"```json\s*(.*?)\s*```", output, re.DOTALL)
```

to extract a JSON block from `gentle-ai sdd-status` markdown output. This command
lives in `internal/sddstatus/` with no versioned schema and no `--output json` flag.

### Why

`gentle-ai sdd-status` is an internal command — its output format is not a public
contract. Any gentle-ai release can change the field names (`changeName`,
`nextRecommended`, `taskProgress`, `dependencies`) or remove the fenced block
entirely. Both scripts would fail silently (return empty strings) with no user
warning.

SDD state is already available through other means:
- `.atl/` files are readable directly by Claude Code
- The SDD orchestrator workflow in `~/.claude/skills/` provides all needed context

### Files touched

- `scripts/user-prompt-submit.py` — remove `get_sdd_status()`, remove SDD section from context injection
- `scripts/session-stop.py` — remove `sdd_snapshot()`, remove SDD section from Engram save
- `tests/test_user_prompt_submit.py` — remove SDD-related test cases
- `tests/test_session_stop.py` — remove SDD snapshot test cases

### What the injected context loses

The `## SDD Status` section in `UserPromptSubmit` context (change name, next phase,
task progress). This was advisory — the SDD skill handles its own state discovery.

## Phase 3 — Remove auto-side-effects ✅ DONE

**Effort:** ~1h

### 3a — Remove `ensure_gga()` from session-start.py

`ensure_gga()` calls `gga install` on every session start if `gga` is in PATH and
the project has a `.git/` directory. This auto-installs a pre-commit hook without
explicit user opt-in.

**Why this is wrong:** A plugin must not modify `.git/hooks/` without the user
explicitly requesting it. If the user has a custom pre-commit hook, this silently
clobbers it. Document `gga install` as a manual one-time step in `README.md`.

### 3b — Remove `check_codegraph_mcp()` from session-start.py

`check_codegraph_mcp()` reads `~/.claude/settings.json` and checks for
`data["mcpServers"]["codegraph"]`. This bypasses the gentle-ai CLI entirely and
couples to Claude Code's settings schema.

**Why this is wrong:** `gentle-ai doctor` already checks CodeGraph MCP configuration.
Reading Claude Code's internal settings file is the plugin's domain; it should not
be. Delegate this check to `gentle-ai doctor`.

### Files touched

- `scripts/session-start.py` — remove `ensure_gga()`, remove `check_codegraph_mcp()`
- `tests/test_session_start.py` — remove GGA and codegraph MCP test cases
- `README.md` — document `gga install` as a manual setup step

## Phase 4 — Remove manual Engram session round-trip ✅ DONE

**Effort:** ~1h

### What to do

Remove `load_session_snapshot()` from `session-start.py` and the `engram save`
call from `session-stop.py`.

Current flow:
```
Stop hook → engram save session-end:{project} "{sdd} | {review} | {git}"
SessionStart hook → engram search session-end:{project} --limit 1 → inject 2000 chars
```

### Why

The Engram MCP server (`mem_session_summary`, `mem_context`) already handles
cross-session continuity natively and correctly. The manual CLI round-trip:

1. Creates two separate interfaces to the same store (CLI vs MCP)
2. Formats a pipe-delimited string that has no schema
3. Reads back raw arbitrary text from the previous session
4. Has three separate JSON shape fallbacks because the `engram search` output is inconsistent

The MCP server is the correct interface. Claude Code already loads it via the
`mcpServers.engram` configuration that gentle-ai installs.

### Files touched

- `scripts/session-start.py` — remove `load_session_snapshot()`, remove snapshot from additionalContext
- `scripts/session-stop.py` — remove `engram save` call, simplify to just gate message
- `tests/test_session_start.py` — remove snapshot recovery test cases
- `tests/test_session_stop.py` — remove Engram save test cases

## Phase 5 — Schema-bound review output parsing ✅ DONE

**Effort:** ~2h
**Priority:** Lower — current parsing works, this is robustness

### What to do

Replace ad-hoc `.get("action", "")` and `.get("context", {}).get("denial", {}).get("code")`
lookups with validation against the `gentle-ai.review-integration/v1` JSON schemas.

The schemas live at:
```
contracts/review-integration/v1/schemas/
  status-v2.schema.json
  start-v2.schema.json
  capabilities-v1.4.schema.json
  result-artifact-v2.schema.json
```

The hardcoded denial code table in `session-stop.py`:
```python
DENIAL_HINTS = {
    "candidate-or-paths-mismatch": "...",
    "invalidated": "...",
    "authority_corrupted": "...",
    "receipt_missing": "...",
}
```
will silently fall back to `f"code={denial_code}"` if gentle-ai adds or renames codes.

### Approach

Use `gentle-ai review schema reviewer` (which prints the JSON schema to stdout) or
fetch the schema at startup and cache it. Validate response structure before
attribute access. On schema mismatch, log a warning and fail-open rather than
silently returning empty strings.

### Files touched

- `scripts/gentle_ai.py` — add `parse_review_status(raw: str) -> dict` with schema validation
- `scripts/user-prompt-submit.py` — use new parser
- `scripts/session-stop.py` — use new parser, remove hardcoded DENIAL_HINTS
- `tests/` — add schema validation test fixtures
